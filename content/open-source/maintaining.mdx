## The problem

A public repository accumulates issues, questions, dependencies, and pull requests. Without a visible process, contributors wait without knowing what happens next.

## Concept

Maintaining means defining scope, triaging work, reviewing contributions, releasing changes, and keeping the project safe. Maintainers are stewards of the project, not an unlimited support team.

## Example

```text
Report → reproduce → label → prioritize → assign or decline
PR → understand intent → review → request changes or merge
Release → notes → deploy → observe → fix or roll back
```

A clear “not in scope” response is more useful than silence when it explains the boundary.

## How it works

A small project can use a README, issue templates, contribution guide, CI, and release notes before it needs complex governance. Reviewers should explain decisions and protect beginner-friendly issues. Contributors should respect maintainer time by providing reproduction steps and running checks.

## Common mistakes

- Accepting every feature and creating a product nobody can maintain.
- Treating contributors as free labor without acknowledging their work.
- Letting stale instructions or broken CI make first contributions harder than they need to be.

## Practice

Review a repository's last five issues. Which need reproduction, which are ready to implement, and which are outside its stated scope? Draft one courteous response that gives a concrete next step.

## Checkpoint

Name three pieces of information a maintainer should provide so a new contributor can make a small change independently.
