## The problem

A contributor writes a good fix, but it arrives in the wrong format, omits required checks, or changes a direction the maintainers are not accepting.

## Concept

`CONTRIBUTING.md` is the repository's local collaboration contract. It explains setup, where content lives, how to propose work, what checks to run, and what a useful pull request includes. Read it before starting, even if you have contributed elsewhere.

## Example

ZERO → HERO's [contribution guide](https://github.com/CharlieJamesGwapo/zero-to-hero/blob/main/CONTRIBUTING.md) asks for focused changes, verified examples, and relevant checks. To improve a lesson, edit its MDX source, preview it locally, and include the reason in your PR.

## How it works

The guide reduces repeated reviewer questions and makes participation predictable. It should be short enough to follow and accurate enough to trust. If the documented command fails, report the discrepancy rather than silently inventing a different process.

## Common mistakes

- Ignoring the guide because a change is “only documentation.”
- Running commands from an older README without checking current scripts.
- Treating a maintainer's requested scope as a personal rejection.

## Practice

Read the guide and locate the exact files needed for a glossary correction. Write a four-step plan: source edit, local preview, check command, and PR description.

## Checkpoint

What would you do if the contribution guide and the actual repository scripts disagree?
