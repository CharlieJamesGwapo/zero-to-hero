## The problem

You understand the terms but have never taken a real change from an issue to a reviewed pull request. The first attempt should be small enough to finish.

## Concept

Your first contribution is a complete engineering loop: find a real need, understand project rules, make a focused change, verify it, request review, and respond to feedback. A merged PR is a possible outcome, not a promise.

## Example

```text
GitHub account → configure Git → fork → clone → branch
→ issue or clear correction → edit → run checks → commit
→ push → pull request → review → possible merge
```

For ZERO → HERO, use the [repository](https://github.com/CharlieJamesGwapo/zero-to-hero), [live Issues page](https://github.com/CharlieJamesGwapo/zero-to-hero/issues), and [CONTRIBUTING.md](https://github.com/CharlieJamesGwapo/zero-to-hero/blob/main/CONTRIBUTING.md). Do not assume a particular issue number exists.

## How it works

1. Create a GitHub account if you do not have one, and set your Git author name and email.
2. Read the README, contribution guide, code of conduct, and security policy.
3. Choose a small open issue, or document a factual correction. Confirm the task is still welcome.
4. Fork and clone, create a branch, and make only the intended change.
5. Run `npm install`, `npm run dev`, `npm run lint`, `npm run typecheck`, `npm test`, and `npm run build` as relevant. Inspect the page in a browser.
6. Review `git diff`, commit, push your branch, and open a PR to the original repository. Link the issue and list checks actually run.
7. Respond to questions with evidence or an updated commit. Maintainers decide whether to merge; they may request changes or decline work that does not fit the project.

## Common mistakes

- Choosing a large architectural rewrite as a first PR.
- Skipping the project's local checks because the change is “just text.”
- Treating a review request as proof your work has no value.

## Practice

Pick one sentence in a lesson that could be clearer. Draft an issue or correction proposal with the exact page, current wording, revised wording, and reason. If the change is accepted in scope, complete the workflow above.

## Checkpoint

Can a reviewer understand your change and reproduce your verification from the PR alone? What would you add if they could not?
