## The problem

Tutorial exercises can feel disconnected from the repository where real developers review changes. You need a project with actual source, rules, and maintainers.

## Concept

ZERO → HERO is itself a public project. Its lessons are MDX files, its routes are Next.js pages, and its checks can run locally. A beginner contribution can improve one explanation, example, link, accessibility detail, test, translation, or glossary definition.

## How it works

**Your first contribution:** beginner scope, roughly 30–60 minutes for a small documentation fix once your tools are set up. You will use Git, GitHub, Markdown or MDX, and code review. Start by cloning your fork, installing dependencies, previewing a page, changing one thing, running the repository checks, and opening a focused PR.

## Common mistakes

- Inventing an issue number instead of checking the live Issues page.
- Editing generated output instead of `content/` or `src/` source.
- Promising a merge or a fixed review time. Maintainers assess each proposal.

## Practice

Open the real repository. Identify one active issue or one concrete documentation correction. Record the file, expected change, verification step, and any question to ask before implementation.

## Checkpoint

Show a reviewer the issue or correction, your branch diff, local checks, and the PR description. Explain what changed and why.
