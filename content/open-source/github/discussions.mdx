## The problem

You have a question or a design proposal, but it is not yet a clear task with acceptance criteria.

## Concept

A discussion is a place to explore questions and choices in public when a project has Discussions enabled. An issue is better once there is a specific change to track. A pull request is for a concrete code or content proposal.

## Example

```text
Discussion: Should beginner Git examples use a local-only project first?
Issue: Add a local-only Git exercise with status and commit checks.
Pull request: Add the exercise and link the issue.
```

If a repository does not enable Discussions, use the communication channel described in its README or CONTRIBUTING guide.

## How it works

A useful discussion names the learner problem, evidence, options, and tradeoffs. Maintainers may answer, turn it into an issue, or decide that no change is needed. Public decisions help future contributors understand why a pattern exists.

## Common mistakes

- Treating a question as a bug report before checking the documentation.
- Opening a pull request for a major new direction without prior discussion.
- Assuming every proposal must be accepted; maintainers balance scope and upkeep.

## Practice

Write a five-sentence proposal for improving one ZERO → HERO page: learner problem, affected page, example, proposed change, and a question for maintainers. Do not post it until you have checked the repository's current contribution channel.

## Checkpoint

Choose between discussion, issue, and pull request for a question, a reproducible broken link, and a completed typo fix. Explain each choice.
